# fdtfile:
#   Which device tree the boot script loads from /dtb/.
#   Default (and correct for almost everyone): meson8b-ws1508.dtb.
#   That file is right on BOTH variants -- on a raw-NAND unit the eMMC
#   controller it enables simply finds no card, which costs nothing.
#
#   The one alternative is the raw-NAND variant:
#
#     fdtfile=meson8b-ws1508-nand.dtb
#
#   It is EXPERIMENTAL and only makes sense on a unit where
#   'ws1508-info' reports "store: raw NAND". Setting it on any other
#   unit is a no-op rather than a brick: boot.scr checks the
#   bootloader's own ${store} detection and, on anything that is not
#   raw NAND, prints a line saying so and loads meson8b-ws1508.dtb
#   instead. The check exists because this dtb disables the controller
#   an eMMC unit's rootfs lives on, and the resulting rootwait hang
#   would leave this very file unreachable. What it does:
#     - disables the eMMC controller (&sdhc). Those are the same BOOT_x
#       pads as the NAND bus, so the two can never both be enabled. On a
#       NAND unit there is nothing on them to lose. The SD card slot is
#       a different controller (&sdio) and is NOT affected.
#     - enables the S805 raw-NAND controller. IF the driver enumerates
#       the fitted die you get two MTDs: /dev/mtd0 "vendor" (the first
#       384MiB, read-only, holding the bootloader, its environment, the
#       per-unit keys and the partitions the bootloader reads) and
#       /dev/mtd1 "ubi" (the rest, which Linux owns). That "if" is real:
#       this driver has never run on meson8b silicon, so nand_scan()
#       failing outright, or reads of vendor-written pages coming back
#       ECC-uncorrectable, are both expected possibilities rather than
#       bugs to report as regressions.
#
#   You need this line to INSTALL to NAND -- 'ws1508-install-to-nand'
#   needs /dev/mtd1 to exist -- but not to BOOT from NAND. A box that has
#   already been installed gets its device tree out of the Android
#   boot.img in the vendor "boot" partition, and never reads this file at
#   all: there is no filesystem on NAND for the bootloader to read it
#   from. Changing anything here after installing therefore only affects
#   USB and eMMC boots. The NAND kernel command line lives in the u-boot
#   environment instead, as ${nandargs}, editable with setenv/saveenv.
#   What it does NOT do:
#     - selecting it does not by itself boot the box from internal
#       storage. That is boot_nand in the u-boot environment, which runs
#       only after USB, SD and eMMC have all failed, and which needs the
#       kernel already installed in the vendor "boot" partition. This
#       line is what the RUNNING system needs (to see the flash at all,
#       and to install to it); it is not the boot switch.
#     - it does not give you writable internal storage. The MTD is
#       read-only unless you also add meson_nand.allow_write=1 to
#       extraargs. There are two barriers, not one: without that
#       parameter the whole MTD is read-only, and the address guard
#       refuses four operations inside the vendor bootloader region
#       whatever the parameter says - erase, program, OOB write and
#       mark-bad. The mark-bad one matters most: nand_block_markbad
#       reaches nand_erase_nand() without passing mtd->_erase, so it is
#       how "nandtest --markbad" would otherwise erase block 0 after an
#       erase is refused. Both barriers are untested on hardware like
#       everything else here, and the image does ship mtd-utils
#       (nanddump's package also carries flash_erase, nandwrite,
#       nandtest and ubiformat). Point nothing but nanddump at
#       /dev/mtd0.
#
#   Before you try it: have a working Amlogic USB Burning Tool setup.
#   That is the only unbrick path, and it restores firmware but NOT the
#   per-device nkey/nsec blobs in the vendor reserved area -- those are
#   gone for good if they are overwritten, and nothing this project
#   ships can write them back. The dump 'ws1508-nand-probe' offers is a
#   diagnostic sample for comparing against a vendor-u-boot read, not a
#   restorable backup: the ECC/scrambler settings are unvalidated so the
#   contents may be wrong, it captures no OOB, and the driver refuses
#   that region categorically. A real nkey/nsec backup, if one is
#   possible at all, has to be taken with the vendor u-boot's
#   amlnf/store commands over the serial console.
#
#   If the box comes up on meson8b-ws1508.dtb anyway, read the boot log
#   or dmesg: boot.scr refused this line because ${store} did not say
#   raw NAND. If it does not come up at all, put the USB stick back in
#   and delete this line.
